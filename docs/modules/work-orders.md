# Work Orders Module

## Overview

The Work Orders module bundles approved sales order lines into production-ready work orders. It handles two distinct production workflows: Offset/Digital (sheet-based) and Flexo (roll-based). Each work order captures an immutable snapshot of the order state at creation time.

## Tables

| Table | Purpose |
|-------|---------|
| `work_orders` | WO header (WO number, date, status, snapshot_json) |
| `work_order_jobs` | SO lines assigned to a work order |
| `work_order_materials` | Raw materials required per WO |
| `work_order_routing` | Process routing steps |
| `wo_sequence` | WO number auto-increment |

## WO Number Format

Generated by `generateWorkOrderNumber()` / `generateFlexoWorkOrderNumber()`:
- Offset: `WO-{FY}/{SEQ}` (e.g., `WO-2526/0042`)
- Flexo: `FWO-{FY}/{SEQ}` (e.g., `FWO-2526/0015`)
- Both share the same sequence counter in `wo_sequence`

## Two WO Types

### Offset/Digital Work Orders (WOW module)

Sheet-based production. Key calculations:
- **Paper selection**: Stock type, GSM, deckle, cut size
- **Sheet calculations**: Core sheets = order qty / UPS, plus wastage
- **Print style**: Single Side, Front-Back, Work-Turn, Work-Tumble
- **Coating**: None, Aqueous, UV, Drip Off
- **Corrugation**: 2-ply making, flute type (B/E), sheet pasting

### Flexo Work Orders (FLEXOWO module)

Roll-based production. Key calculations:
- **Cylinder/teeth-based**: Teeth count determines repeat length
- **Running meters**: Calculated from order qty, UPS, and teeth
- **Label types**: Front, Back, Top, Bottom, Neck, Flat Label, Single, Set
- **Winding direction**: Clock Wise, Anti Clock Wise, Sheet Form
- **Finished format**: Sheet Form, Roll Form, Fan Fold, Cut Label, Pcs, Unit
- **Die types**: Rotary Die, Flatbed Die, None

## WO Candidate View

`v_workorder_candidates` determines which SO lines are eligible for WO creation:

- `accounts_status` = APPROVED
- `business_status` = APPROVED
- `artwork_status` = APPROVED
- SO status is not CANCELLED
- `remaining_qty` > 0 (order qty minus already-processed qty)
- Product is not a service-only item (SLC001: Flexo Plate, SLC002: Offset Plate, SLC003: Die)
- For offset WO: `department_category` is not FLEXO (flexo has its own flow)

The view also calculates `approval_stage` (human-readable text) and `can_create_wo` (boolean flag).

## Key Functions (Code.gs)

| Function | Purpose |
|----------|---------|
| `listSOWithStatus(limit, offset)` | List SOs with WO eligibility status |
| `listFlexoWOStatus(limit, offset)` | List SOs with Flexo WO eligibility |
| `saveWorkOrder(payload, options)` | Create/save an offset/digital work order |
| `saveFlexoWorkOrder(payload)` | Create/save a flexo work order |
| `getWorkOrder(woNo)` | Load a complete WO with jobs, materials, routing |
| `printWorkOrder(woNo)` | Get WO data formatted for printing |
| `deleteWorkOrder(woNo)` | Delete a WO (cascades to jobs, materials, routing) |
| `saveAndExportWO(payload)` | Save WO and return print-ready data |

## Snapshot JSON

The `snapshot_json` field on `work_orders` captures the complete state of the order at WO creation time. This is an immutable reference used by production views:

```json
{
  "jobs": [{ "soNumber": "SL-2526/0001", "lineNo": 1, "qty": 1000, "ups": 4, "coreSheets": 250 }],
  "papers": [{ "stock": "Art Paper", "gsm": 130, "deckle": 23, "cutSize": 36, "sheets": 280 }],
  "routing": [{ "department": "Printing", "machine": "Heidelberg SM74" }],
  "wastage": { "processSheets": 30 },
  "jobDetails": { "type": "Offset" },
  "flexoDetails": { "totalRunningMeter": 5000, "baseRunningMeter": 4500 },
  "modeOfTransport": "Road"
}
```

Production views extract planned quantities from this snapshot (e.g., `paper_sheets_with_waste` for stage 1 planning).

## Materials

Each WO has materials with a unique `material_key` (enforced by `uq_wom_material`):

| Field | Description |
|-------|-------------|
| `material_key` | Composite key identifying the material (e.g., paper type + GSM + size) |
| `required_qty` | Total material required |
| `uom` | Unit of measure |
| `item_code` / `item_id` | Links to inventory item |

`buildWOMaterialRequirementRows_()` calculates requirements from the WO snapshot. Materials connect to inventory for issue tracking via `wo_material_pending` view.

## Routing

Process steps with sequence numbers. Available departments and machines are defined in `DEFAULT_MASTERS.machinesByDept`:

| Department | Example Machines |
|-----------|---------|
| Printing | Heidelberg SM74, CD102, UV 2 Color Machine |
| Lamination | Lamination 01-04 |
| Die Cutting | Die Cutting 01-03, Automatic Die Cutting |
| Flexo Printing | Markany Flexo E5 |
| Packing | Packing Machine, Manual Packing |

Routing status per step: PENDING, IN_PROGRESS, COMPLETED, SHORT_CLOSED, HOLD

## Views

| View | Purpose |
|------|---------|
| `v_workorder_candidates` | SO lines eligible for WO creation |
| `wo_material_pending` | Materials pending issue from inventory |

## Integration

- **Sales Orders**: WO jobs reference SO number + line_no; WO status rolls up via cache triggers
- **Inventory**: WO materials drive inventory issue; `invListWorkOrdersForIssue()` lists WOs needing material
- **Production**: Production entries recorded against `work_order_routing` steps
- **Artwork**: Artwork data flows into WO snapshot at creation time
